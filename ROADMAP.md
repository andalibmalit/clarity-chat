# Roadmap

What the next releases hold. Each release has a written plan, so later entries can change. From v0.2.3 to 0.8.0 the releases are built in one sprint: each gets its plan, reviews and QA pass, and the maintainer uses the whole as a user would after 0.8.0, through extended use, rather than each release before its tag. The exceptions are the first runs on real Linux and Windows machines, which come with v0.6.0 and v0.7.0. Released versions and their changes are in [`CHANGELOG.md`](CHANGELOG.md); v0.2.0 built in the terminal the core a graphical interface needs, v0.2.1 added resampling, token probabilities and export, v0.2.2 added steering on the Transformers backend, v0.2.3 the commands the web interface reads: comparing replies, every branch, any reply by its call ID, and where things are mid-reply, v0.3.0 the web interface on macOS (`clarity ui`), with Llama 3.1 8B, Instruct and base, among the shipped models, v0.3.1 attaching a document (text, HTML or PDF) to a message, whole or in part, in the terminal and the web interface, v0.3.2 searching your documents by words, with what each message found logged with it and replayed exactly, v0.4.0 the exactness core: a model file's banned tokens recorded and checked, replay finding a call's model by its file, a warning for chat templates that write the date, control characters shown in `/prompt`, and your own model entries in `local/models.toml`, v0.4.1 searching your documents by meaning, by default, with a local embedding model (bge-m3), and v0.4.2 a one-command install for Macs with Apple silicon, whose setup step builds llama.cpp, fetches Gemma 4 E4B and bge-m3, and puts a launcher on the Desktop.

- **Next: v0.4.3, export for Inspect.** Clarity's calls written as Inspect AI eval logs, to browse and compare in `inspect view` and score later with `inspect score`.
- **v0.4.4, settings on the page.** Context presets, the page's settings for searching documents, and screenshots of the web interface in the README.
- **v0.5.0, thinking models.** Reasoning stored with each reply, and the extra samplers these models use.
- **v0.6.0, Linux.** CUDA, Vulkan and CPU builds, with the GPU driver and CUDA version logged. Check, on a real CUDA and Vulkan run, how the GPU placement check reads llama.cpp's `CUDA_Host` and `Vulkan_Host` buffers.
- **v0.7.0, Windows.**
- **0.8.0, the reviewed candidate.** Cross-platform, and easy to install for people who don't use a terminal. Before 0.8.0, a full-project review by parallel agents, each finding independently checked, plus a QA pass. 0.9 releases fix what extended use finds.
- **1.0.** When extended use shows that the log format, profile keys, commands and the replay promise hold.
- **Later, not scheduled.** Import of chats from other apps. Live probe readings, when an experiment needs them. Steering on llama.cpp through its control vectors, and comparing a steered reply across the two backends.
